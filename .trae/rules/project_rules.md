# 简忆 · 项目规则

本文件是项目的长期约定。改代码前先看这里，与这里冲突的方案一律以这里为准。

## 1. 项目定位

- 应用名：**简忆**（英文：JIAN YI）。任何位置不得再出现「墨记」「Ink Journal」等旧名
- 目标平台：HarmonyOS NEXT，Stage 模型
- 定位：单人使用的本地优先应用，不是社交产品，不做账号体系
- 优先级：能每天用 > 功能多。任何新功能先问「一天会用几次」

## 2. 技术栈

| 层 | 选型 |
|---|---|
| 语言 | ArkTS |
| UI | ArkUI 声明式 |
| 存储 | RelationalStore（SQLite） |
| 偏好设置 | Preferences |
| 通知 | notificationManager |
| 电子书 | Reader Kit |
| 备份 | BackupExtensionAbility |

不引入第三方 UI 框架，不引入 npm 运行时依赖。

## 3. 数据规则

1. 主键统一 `TEXT id`，值用 UUID，**禁止自增整数**
2. 每张业务表必须有 `created_at` / `updated_at` / `deleted_at`
3. 删除一律软删除，查询必须带 `deleted_at IS NULL`
4. 时间戳用毫秒 `INTEGER`；只有「按天」语义的字段用 `'YYYY-MM-DD'` 字符串
5. 派生数据不落库（连续天数、未完成计数等），查询时现算
6. 表结构变更必须：`DB_VERSION + 1` + `migrate()` 里追加一段，**禁止直接改建表语句**
7. 数据库字段用 `snake_case`，ArkTS 接口用 `camelCase`，映射写在仓库层

## 4. 代码约定

- 一个业务域一个仓库文件，命名 `XxxRepo.ets`
- 仓库层只做数据读写，**不碰 UI、不碰文件系统**（如删书只返回路径，由调用方删文件）
- 所有可空列读取走 `RowUtil`，不要到处手写 `isColumnNull`
- 查询集中在仓库层，页面里不出现 SQL
- 全局只保留一个 `RdbStore` 实例，通过 `JianYiDb.db()` 获取

## 5. 设计规范

- 色彩只用 CSS 变量（原型）与统一资源（鸿蒙）：纸色 `#F6F2E9`、墨色 `#1B1917`、朱砂 `#B4432E`
- 标题用宋体，正文用无衬线；正文行高不低于 1.9
- 圆角：卡片 16–20，按钮 100（胶囊）
- 动效时长 220–340ms，缓动 `cubic-bezier(.16,.84,.32,1)`
- 空态必须给「下一步做什么」，禁止只写「暂无数据」

## 6. 开发流程

1. 新功能先改原型，确认交互
2. 再定数据模型（字段、索引、是否派生）
3. 最后写代码：数据层 → 页面 → 入口
4. 原型是唯一的产品事实来源，代码与原型不一致时以原型为准并同步更新

## 7. 提交规范

```
feat: 新增 xxx
fix: 修复 xxx
refactor: 重构 xxx
docs: 文档变更
```

一次提交只做一件事，不混入格式化改动。
