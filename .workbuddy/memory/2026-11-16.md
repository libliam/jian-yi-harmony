## 修复：回顾页补标标签切换无反应（用户 17:19 反馈）

- 现象：微光回顾页点维度标签没反应、选了新维度也不换；写库成功、无任何报错。这是微光一期**首次真机反馈** —— 说明 DB v1→v2 迁移、页面栈跳转、一步录入都能跑，坏的只有回顾页补标交互。
- 根因：`ForEach` 非首次渲染只按 key 判断能否复用组件，原 key 只有不变的 `row.id` / `group.date`。key 不变 → 复用旧组件 → itemBuilder 不重跑 → ① `if (this.editingId === row.id)` 不重新求值，补标面板压根不展开；② 标签文本仍是闭包里旧 `row.category`。与官方博客「数据改了、列表不刷新，而且一条报错都不产生」是同一个坑。`@State` 只观察第一层也救不了，换整个数组但 key 不变照样复用。
- 修法：`GrowthView` 加 `@State listVersion`，`load()` 结束与点标签展开/收起时递增；时间线内外层、维度分布、热力四处 ForEach 的 key 都带 `listVersion` 与展示字段（`categoryLabel(row.category)` / `item.count` / `count`）——展示字段进 key 是双保险；补标选项加当前维度深色高亮。`QuickSheet.miniChips` 同类问题一并修（key 从 `kind + opt` 改为带 `current`），否则录入弹层那排 chips 的选中态同样不变。
- 官方约束核对：keyGenerator 只允许读状态、不允许改组件状态；各 ForEach 的 itemGenerator / keyGenerator 是否声明 `index` 两边对称，避免框架自动拼 index。
- 文档：`AGENTS.md` 新增 3.7、能力清单微光行改为「真机已能运行，补标待复验」；`README.md` 进度表同步。
- **本机无 SDK，未编译验证**。真机复验：点标签应弹出七个维度且当前项高亮；选中后标签与「这段日子，长在哪儿」分布条同时变化；录入弹层里点维度 chips 选中态也要跟着变。
