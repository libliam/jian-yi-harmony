# 2026-11-20 · 真机定位：bindContextMenu 8+ 长按重载不触发，三视图换 isShown 受控形式

## 用户真机反馈

- 待办 / 习惯 / 日程三处长按菜单在真机（Mate 60 Pro，API 26）完全无反应，按住 1 秒以上不弹；`f681c61` 的编辑 / 删除功能入口失效。

## 定位过程（不烧 verify_ui 次数的调试路线）

- 先排除落点因素：`uitest uiInput longClick` 精确注入行文本中心坐标（来自 `uitest dumpLayout`），两轮 verify_ui 的触摸日志命中节点都是 Scroll 而非行，证据不干净。
- 对照实验排除注入本身：`longClick` 桌面空地能弹壁纸面板 → 注入是真长按；零位移 `drag` 慢速按住行同样不弹。
- **一个构建放三个候选方案**，装包后分别注入验证：
  1. 8+ 老重载 + 规范 @Builder 引用（`bindContextMenu(this.rowMenu, ResponseType.LongPress)`，builder 读 @State）——**失败**，连长按识别器都不注册；
  2. 显式 `LongPressGesture` + `bindContextMenu12` isShown 受控形式——**成功**，原生菜单子窗正常、编辑预填全通；
  3. `LongPressGesture` + `bindPopup`——**成功**。
- 结论：菜单子窗机制没坏，坏的是 8+ 重载的长按触发（API 26 真机）。已沉淀 AGENTS.md 3.11。

## 修法（三视图统一）

- `LongPressGesture().onAction()` 把长按的行写进 @State（`menuTodo = item` + `todoMenuShown = true`）。
- `.bindContextMenu(带行 id 守卫的布尔表达式, this.rowMenu, { onDisappear: 复位 })`；content 一律无参 @Builder 引用，体内读 `this.menuTodo`（3.10 安全路径①）。
- PlanView 曾临时用 bindPopup 验证过，最终也归一到菜单形式，保持三处一致。
