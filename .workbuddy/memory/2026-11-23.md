# 2026-11-23 · 长按菜单样式对齐纸墨主题

## 用户诉求

长按菜单弹出的是系统默认白底黑字，与 app 的纸墨风格不一致，要求调整样式对齐。

## 改动

- 三个视图（`TodoView.rowMenu` / `SubPages.habitMenu` / `PlanView.slotMenu`）的 `Menu()` 统一加样式：`.font({ size: 14, family: SANS }).fontColor(C.ink).backgroundColor(C.paper).borderRadius(S.smallRadius).width(132)`。
- `MenuItem` 自身没有 `fontColor` / `fontSize`（查 SDK `component/menu_item.d.ts` 确认），「删除」要染朱砂色只能走 `CustomBuilder` 重载：每个 struct 加 `@Builder deleteItem()`，内为 `Row { Text('删除').fontSize(14).fontFamily(SANS).fontColor(C.cinnabar) }`，调用处改成 `MenuItem(this.deleteItem())`；「编辑」保留标准 `MenuItem({ content: '编辑' })` 吃 Menu 的 fontColor。
- 三个文件各加 `SANS` 导入。色彩与圆角全部取自 `Theme.ets`，无硬编码色值。
- `AGENTS.md` 3.11 末尾沉淀接口事实与真机待验项。

## 编译验证

- **工具链变化**：`devecocli` / `arkts_check` 当前不在 Agent 的 PATH 里（此前日志说可用，环境已变）；改用 DevEco 自带 `hvigorw.bat`，且必须临时注入 `DEVECO_SDK_HOME` 与 `DEVECO_HOME`，否则报 `Invalid value of 'DEVECO_SDK_HOME'`。已写进 AGENTS.md 3.1 附注。
- `hvigorw assembleHap --mode module -p product=default --no-daemon` → **BUILD SUCCESSFUL**（47s，17 tasks executed）。警告均为存量：db 层 `Function may throw exceptions`、`getContext` / `showToast` 弃用，无新增错误。

## 待真机复验

- 菜单是否为纸底墨字、圆角是否生效（系统子窗默认背景是否被 Menu 的 backgroundColor 覆盖，编译验证不了视觉）。
- 「删除」朱砂色是否被 `Menu.fontColor(C.ink)` 级联覆盖；若被覆盖，改法是把「编辑」也换成 CustomBuilder，各自显式设色。
- 长按触发与编辑 / 删除回调未动，11-20 已真机验证，理论上不受影响。
