# 2026-11-23 · 长按菜单样式对齐纸墨主题

## 用户诉求

长按菜单弹出的是系统默认白底黑字，与 app 的纸墨风格不一致，要求调整样式对齐。

## 改动

- 三个视图（`TodoView.rowMenu` / `SubPages.habitMenu` / `PlanView.slotMenu`）的 `Menu()` 统一加样式：`.font({ size: 14, family: SANS }).fontColor(C.ink).backgroundColor(C.paper).borderRadius(S.smallRadius).width(132)`。
- `MenuItem` 自身没有 `fontColor` / `fontSize`（查 SDK `component/menu_item.d.ts` 确认），「删除」要染朱砂色只能走 `CustomBuilder` 重载：每个 struct 加 `@Builder deleteItem()`，内为 `Row { Text('删除').fontSize(14).fontFamily(SANS).fontColor(C.cinnabar) }`，调用处改成 `MenuItem(this.deleteItem())`；「编辑」保留标准 `MenuItem({ content: '编辑' })` 吃 Menu 的 fontColor。
- 三个文件各加 `SANS` 导入。色彩与圆角全部取自 `Theme.ets`，无硬编码色值。
- `AGENTS.md` 3.11 末尾沉淀接口事实与真机待验项。

## 编译验证

- **工具链变化**：`devecocli` / `arkts_check` 当前不在 Agent 的 PATH 里（此前日志说可用，环境已变）；改用 DevEco 自带 `hvigorw.bat`，且必须临时注入 `DEVECO_SDK_HOME` 与 `DEVECO_HOME`，否则报 `Invalid value of 'DEVECO_SDK_HOME'`。已写进 AGENTS.md 3.1 附注。

## 追加：菜单改为贴手指的纸墨气泡（用户第二问）

- 用户问「弹出位置都在最前面，不是跟着手指，必须吗？」—— 不是必须，是 `bindContextMenu` 12+ 受控形式默认 `Placement.BottomLeft`（相对组件）导致；8+ 重载才是点击位置，但 API 26 真机长按不触发（3.11）。
- 用户选择「跟手指弹」。三处 `bindContextMenu` 换成 `bindPopup`：
  - `LongPressGesture.onAction((event: GestureEvent) => ...)` 用 `event.fingerList[0].localX/localY` 记录手指坐标到 `@State menuX/menuY`。
  - `bindPopup(shown, { builder, placement: Placement.TopLeft, offset: { x: menuX, y: -menuY }, popupColor: C.paper, backgroundBlurStyle: BlurStyle.NONE, enableArrow: false, mask: false, autoCancel: true, onStateChange })`。
  - builder 从系统 `Menu/MenuItem` 改为自绘 `Column + 两个 Row`：宽 132、行高 44、分隔线 `C.ruleSoft`、删除朱砂。onClick 先置 shown=false 再执行编辑 / 删除。
- **编译踩坑（已修）**：① `GestureEvent` 无 `localX/localY`，要用 `event.fingerList[0].localX`（坐标在 `FingerInfo` 上）；② ArkTS 禁止对象字面量作类型声明，回调参数写 `{ isVisible: boolean }` 报 `arkts-no-obj-literals-as-types`，改为 `interface PopupVisibleState`。首次 build FAIL（10 errors），修后 **BUILD SUCCESSFUL**（25s，无新增错误）。
- **真机待验**：气泡是否贴手指、offset 方向（若反向把 `-menuY` 改成 `menuY`）、编辑 / 删除与软删除回调仍正常。上一轮系统 Menu 样式方案已被本轮取代。
